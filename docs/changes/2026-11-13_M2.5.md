# 2026-11-13 · M2.5 BPF node layout, data zoom (feedback)

## What changed

All in com5fy's frontend (`ui/src/bpf/`, rebuilt into `js/com5fy.js`); no Python changes.
- **Editor on top, ~75% of the node.** In [`register.tsx`](../../ui/src/bpf/register.tsx) the curve editor is now the
  BPF node's first widget, above `duration_ms` … `unit`. The default node size is 560 × 760, which gives the editor
  about 74% of the height (measured: 581 of 790 px). Its minimum height went from 120 to 300 px
  ([`BPFEditor.tsx`](../../ui/src/bpf/BPFEditor.tsx)).
- **Old workflows still load.** Moving the widget changes the order of `widgets_values`, and ComfyUI assigns those by
  position. Workflows saved before this change have the settings first. They are detected (the first value is a
  number, not the points JSON), re-read by name, and the node is grown to 560 × 760. The shipped workflows
  `M2.5_bpf` and `M2.6_descriptor` are rewritten in the new order and relaid out so the taller nodes don't overlap.
- **Zoom to the data.** A curve shown from the `input` is drawn over its data's min..max plus 5% on each side
  ([`Editor.ts`](../../ui/src/bpf/Editor.ts) `dataView`), not over its nominal range. "Edit a copy" still copies the
  nominal range into `min`/`max`. Curves you draw are unchanged: the box is `min`/`max`.

**Commits:** com5fy — "BPF node: editor above the settings at ~75% height, input curves zoomed to their data (M2.5)".

## How to test

1. Reload the browser (frontend only; no restart needed).
2. Open `workflows/M2.5_bpf.json` and `workflows/M2.6_descriptor.json` and press Run.
3. Each BPF node has the curve on top, filling most of the node, with the settings below it.
4. In M2.6, "f0 as a BPF" shows the four notes (220 → 390 Hz) with their vibrato, on a 210–400 Hz axis.
5. Open a workflow you saved before today that has a BPF node: the points and settings are kept and the node grows.

## Known limitations

- **Small nodes:** the editor takes all the free height, so if you shrink a node, the editor shrinks first (down to 300 px).
- **Light theme:** still not looked at.
- **Changing duration/min/max:** this still clips drawn points rather than stretching them.

## Feedback wanted

- Is 560 × 760 a good default size, or should the node be wider and shorter?
- Should "Edit a copy" use the zoomed data range as the new box instead of the nominal range?

## Follow-up: default size back (2026-11-13)

After trying it, the user asked for the node to go back to its default size. The node is 520 × 420 again (new nodes,
and the M2.5/M2.6 workflows with their earlier layout). Old workflows are no longer grown on load, and the editor's
minimum height is 120 px again. The editor stays above the settings and keeps the data zoom.
At 520 × 420 the editor is 141 of 450 px (~31%). The six settings rows (179 px plus gaps), the title, the input row and
the footer use the rest, so ~75% isn't possible at this size while all six settings are shown as rows.
