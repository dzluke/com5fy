# M2.1 feedback: tempo, markings, microtones, viewer zoom, 2026-11-05

Changes made in response to your feedback on [M2.1](2026-11-03_M2.1.md).

## What changed

**Tempo**
- **Score to Sequence no longer has a `bpm` input.** It was only there to override the tempo. Now the timings always
  follow the score's own metronome marks, tempo changes included. m5's `Score.to_sequence(bpm=...)` can still force
  one tempo from a script.
- **A score with no tempo mark is read at 120 BPM**, not 60 (`m5.DEFAULT_BPM`).
- **Sequence to Score estimates the tempo by default.** Its `bpm` input now defaults to 0, which means "estimate it
  from the notes". How the estimate works (new
  [mmmmm/src/m5/tempo.py](https://github.com/dzluke/mmmmm/blob/main/src/m5/tempo.py), `m5.estimate_bpm`):
  - it searches 40–200 BPM for the beat that puts the onsets on the simplest subdivisions (on the beat, then eighths,
    triplets, sixteenths…)
  - it allows about 12 ms of timing slack, so played or analysed timings still fit
  - it prefers tempos where most beats have a note
  - when the notes fit several tempos equally well, it picks the one nearest 100 BPM
  - on the test score it recovers ♩=90, and it recovers 72, 90, 100, 120 and 144 when the same notes are timed at
    those tempos
- **The tempo mark now shows in the score.** `from_sequence` put the metronome mark outside the parts, so the MusicXML
  export dropped it. It is now in the first part.
- **The Orchidea node keeps 60 BPM.** Its segments come from onset detection, not from a beat, so its score looks the
  same as before.

**Dynamics and playing styles** ([score.py](https://github.com/dzluke/mmmmm/blob/main/src/m5/score.py))
- Score to Sequence puts a dynamic or a text expression ("pizz.") **only on the note where the marking appears**. A
  marking over a rest goes on the next note.
- Sequence to Score still writes a marking only when it changes. Orchidea's Sequences repeat the dynamic on every event,
  and they still get one marking per change.

**Microtones**
- In a Sequence, a microtone is written as **the nearest tempered pitch plus a deviation of at most ±50 cents**. Data
  formats usually do it this way (Orchidea, MIDI pitch bend, the cents marks in spectral scores). Examples: C +70 cents
  becomes `C#4` −30, and a B quarter-flat stays `B4` −50.
- Sequence to Score writes ±50 cents as **quarter-tone accidentals** (MusicXML `quarter-flat`, `three-quarters-sharp`
  …), as notation software shows them. Other deviations become fractional alters. Before this change the MusicXML
  dropped microtones completely.

**Sequence Viewer** ([ui/src/sequence/](../../ui/src/sequence/), [nodes/data.py](../../nodes/data.py))
- **`zoom` replaces `pixels_per_second`.** At 1 one second takes 120 px, 2 spreads the events twice as far apart, and
  0.5 fits twice as much. Changing it **redraws the viewer at once**, without running the workflow, and keeps the view
  on the same moment in time.
- **Markings are shown as in a score:**
  - dynamics in bold italic under the staff, and text styles (pizz., arco) in italics above it. Each is shown only
    where it changes on that staff.
  - articulations as their usual symbols on the notehead side: staccato, staccatissimo, accent, tenuto, marcato,
    up-bow and down-bow, harmonic, snap-pizz. Articulations without a symbol are written as text above the staff.
  - labels that would overlap are stacked in rows
- **Microtones:** ±50 cents is drawn as a quarter-tone accidental. Any other deviation keeps its accidental and gets a
  small cents label such as "+14". Each pitch of a chord gets its own value.

**Score Viewer**
- OSMD 1.9.0 crashes on a rest in a second voice next to a quarter-tone note. The re-quantized test score hit this
  once quarter tones were exported. When a render fails, the viewer now retries with each rest placed explicitly on
  the middle line.

**Workflows:** [M2.1_score_sequence.json](../../workflows/M2.1_score_sequence.json) (with a new Note) and its API
version are updated. In [M1.4_w1_audio_to_score.json](../../workflows/M1.4_w1_audio_to_score.json) and
`api/W1_audio_to_score.json`, the viewer now has `zoom` = 1.

## How to test

1. Restart ComfyUI (Python changed), and reload the browser.
2. Open `custom_nodes/com5fy/workflows/M2.1_score_sequence.json` and press Run.
3. What you should see:
   - **Sequence Viewer:**
     - flute: *p* under the first note, staccato dots, a tenuto, the B with a quarter-flat sign, an accent, *f*
     - cello: *pizz.* and *mf* on the first note, *arco* later, *pp* at the end
   - **Zoom:** set it to 0.5 or 2. The viewer redraws at once, with no Run needed.
   - **Back to a score:** it shows ♩ = 90. That tempo was estimated, since `bpm` is 0. The first bars match the
     original, the quarter-flat B included.
4. Things to try:
   - Sequence to Score `bpm` = 120, which forces a tempo
   - a MusicXML file with no tempo mark in Load Score: its sequence is timed at 120 BPM
   - an Orchidea workflow (M1.4): the score should look as it did, and the Sequence Viewer shows each dynamic or style
     once, where it changes

Tests: `cd mmmmm && uv run pytest -m ""` (85 pass) and `uv run --with pytest pytest custom_nodes/com5fy/tests -m ""`
(42 pass). `uv run python custom_nodes/com5fy/workflows/run.py --all`: all 3 pass (W1 with Orchidea included).

## Known limitations

- **Half or double tempo is a judgement call.** A run of sixteenths at 60 BPM sounds the same as eighths at 120. The
  estimator prefers tempos near 100 BPM, so a score at ♩=60 full of sixteenths may come back at 120 with eighths.
- **There is still one tempo on the way back.** The estimate is a single tempo for the whole Sequence, so the 120 BPM
  section of the test score is still approximate. A Sequence has no tempo map until M2.2.
- **A repeated identical marking is dropped.** For example, a second *p* with no other dynamic in between doesn't come
  back on the way back to a score.
- **Viewer label sizes are estimates.** Row stacking uses an estimated text width, so very long playing-style texts
  can still touch.
- **The rest workaround only runs after a failure.** When OSMD fails, every rest in the score is pinned to the middle
  line, including rests it would otherwise have moved out of a second voice's way.

## Feedback wanted

- **Articulations as symbols:** the viewer draws staccato, accent and the like as symbols, as the score does. Would you
  rather have them as words ("stacc.")?
- **Estimated tempo:** does the preference for about 100 BPM pick the tempo you would write? Should the search range
  (40–200) change?
- **Orchidea at 60 BPM:** should Orchidea's score keep the fixed 60 BPM, or use the estimate too?
- **Zoom:** is 1 = 120 px/s a good default? Would you also like Ctrl/⌘ + scroll inside the viewer to zoom?
