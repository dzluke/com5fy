# M3.4: MIDI Viewer (piano roll + basic synth), 2026-11-13

M3.7 (Audio node history) was skipped by the user's decision: it needs the shared history mechanism (M3.1/M3.2),
which needs M2.7/M2.8 first.

## What changed

**m5** (`mmmmm`)
- [`synth.py`](../../../../mmmmm/src/m5/synth.py): `m5.synthesize_midi(midi, sample_rate=44100, normalize=True) -> Audio`.
  This is a basic additive synth (one soft tone with 5 harmonics and ADSR for every program; channel 10 drums are
  noise hits). Velocity sets loudness (velocity²), it follows pitch bend while a note sounds (microtones, glides), and
  the sustain pedal (CC64) holds released notes until the pedal comes up. Output is mono, normalized only if it clips.
- [`midi.py`](../../../../mmmmm/src/m5/midi.py): `Midi.detuning_cents(note)`, the bend at a note's start in cents.
- Tests: `tests/test_synth.py` (7).

**com5fy**
- `m5_MidiViewer` ("MIDI Viewer", `m5/data`, [`nodes/data.py`](../../nodes/data.py)): a piano roll plus playback,
  with the MIDI passed through. It has:
  - one row per key, with a keyboard on the left and the C's labelled;
  - one color per track, with a legend;
  - softer notes drawn fainter;
  - microtones (bend at a note's start) drawn between rows;
  - barlines, measure numbers and beat lines from the file's time map;
  - a hover tooltip;
  - play/pause, and click or drag to seek;
  - a `zoom` input (1 = the whole file in view; higher values scroll sideways) that redraws live, with the view
    following the playhead.

  Frontend: [`ui/src/midi/`](../../ui/src/midi/) (`PianoRoll.ts`, `MidiViewer.tsx`, `register.tsx`).
- `m5_MidiToAudio` ("MIDI to Audio (basic synth)", `m5/convert`): the same synth as an AUDIO output (`sample_rate`
  is an advanced input).
- **Fix:** clicking or dragging on Audio Playback's waveform did not seek. The native `pointerdown` stop on the
  widget root kept React 18's root listener from ever seeing the event. Both players now stop it with a React
  handler. A note about this went into `CLAUDE.md`.
- Workflow [`workflows/M3.4_midi_viewer.json`](../../workflows/M3.4_midi_viewer.json) (+ `api/` version), tests
  `tests/test_midi_viewer.py` (5).

Commits: see the session log line in the plan (mmmmm: synth; com5fy: MIDI Viewer, MIDI to Audio, Audio Playback
seek fix).

## How to test

1. Restart ComfyUI (Python changed). Reload the browser.
2. Open `custom_nodes/com5fy/workflows/M3.4_midi_viewer.json`. `m5_duo_cc.mid` must be in `input/`; copy it from
   `workflows/inputs/` if needed.
3. Press Run. Then:
   - **Top viewer:** Clarinet (blue) and Piano (orange), bars 1–4. Bar 3 is longer (75 BPM) and so is bar 4 (4/4). The
     clarinet's 4th note sits half a row above A4 (+50 ¢). Hovering it shows `A4 +50¢ (69) vel 90`.
   - **Playback:** press ▶ to hear the synth. Sounding notes get a white outline. Click on the roll to jump. Bar 2's
     piano chord rings on (pedal) until bar 3, and the A4 is audibly a quarter tone sharp.
   - **Zoom:** set `zoom` to 4 and scroll sideways with the wheel, trackpad or scrollbar.
   - **Basic synth rendering (Audio Playback):** the same sound as AUDIO. Clicking the waveform now seeks.
   - **Bottom viewer:** the M2.1 duo score converted to MIDI. Velocities come from the dynamics, and the flute's
     quarter-flat sits between rows.

## Known limitations

- **Vertical layout:** the pitch range (the file's notes ±2 semitones, at least two octaves) always fills the height.
  There is no vertical zoom or scroll, so a piece spanning 7 octaves gets thin rows (make the node taller).
- **Synth sound:** the synth ignores programs, volume (CC7), expression (CC11) and other controllers. Every track
  sounds the same.
- **Tempo and meter label:** only the first tempo and meter appear in the controls row. Changes show only as bar
  spacing.
- **History:** no version history (◀ ▶) yet; that comes with M3.1/M3.2.

- **Controller lanes:** should the viewer also draw controller lanes (CC, pitch bend) under the roll, or is MIDI to
