# M2.1: Score ⇄ Sequence, 2026-11-03

## What changed

**m5 ([mmmmm/src/m5/score.py](https://github.com/dzluke/mmmmm/blob/main/src/m5/score.py))**
- **`Score.to_sequence(bpm=None)`**, the inverse of `Score.from_sequence`:
  - each part becomes a sub-Sequence, with one Event per note, chord or unpitched note at its time in ms
  - rests become gaps between events, and tied notes become one Event
  - timings follow the score's metronome marks, including tempo changes and dotted-quarter (or other) referents. A
    score without marks uses 60 BPM. Pass `bpm` to force one tempo.
  - each Event keeps `pitch`, `instrument`, `dynamic`, `playing_style`, `velocity` and `detuning_cents`, plus any
    editorial values as custom fields
  - dynamics and text expressions ("pizz.", "arco") are treated as state: every note after a marking carries it
  - articulations are added to `playing_style` after the text expression, as names like `"staccato"`, `"tenuto"`,
    `"strong-accent"`
  - microtones (music21 microtones and quarter-tone accidentals) become `detuning_cents`, one value per pitch
- **`Score.from_sequence` changes:**
  - it reads m5 pitch names: `b` flats, `x` double sharps, and `-` only as the octave sign (`"C-1"`). Before this,
    `"Bbb3"` crashed and `"C-1"` was read as C♭1.
  - per-pitch `detuning_cents` works on chords
  - articulation names in `playing_style` become real articulations again
  - Sequence → Score → Sequence is now exact
- Decisions are written up in plan §2.3 ("Score ⇄ Sequence details").

**com5fy ([nodes/convert.py](../../nodes/convert.py))**, both nodes in the new `m5/convert` menu category:
- **Score to Sequence** (`m5_ScoreToSequence`): Score → Sequence. Its `bpm` input defaults to 0, which means use the
  score's own tempo marks.
- **Sequence to Score** (`m5_SequenceToScore`): Sequence → Score. Inputs:
  - `quantization`: half … sixty-fourth, or `none` for exact timings
  - `bpm`: default 60
- New fixture [tests/data/duo_tempo_dynamics.musicxml](../../tests/data/duo_tempo_dynamics.musicxml): flute and cello
  with a tempo change, dynamics, articulations, pizz./arco, a tie and a quarter-flat.
- Workflows: [workflows/M2.1_score_sequence.json](../../workflows/M2.1_score_sequence.json) (UI, with a Note) and
  [workflows/api/M2.1_score_sequence.json](../../workflows/api/M2.1_score_sequence.json) (headless runner, no external
  dependencies).

## How to test

1. Restart ComfyUI (Python changed).
2. Open `custom_nodes/com5fy/workflows/M2.1_score_sequence.json` and press Run.
3. Expected:
   - **Original score** shows "Duo" for flute and cello, at ♩=90 changing to ♩=120.
   - **Sequence Viewer** shows the same notes on a time axis. The flute's run after the tempo change is visibly
     tighter. Hover or inspect the notes to see the dynamics, pizz./arco and the −50 cents on the quarter-flat B.
   - **Back to a score** is the Sequence quantized again at 90 BPM on a sixteenth grid. The first bars match the
     original: pitches, tie, staccato/tenuto/accent, p/f/mf, pizz./arco.
4. Try:
   - Score to Sequence `bpm` = 120, which ignores the score's marks
   - Sequence to Score `quantization` = `none`, or a different `bpm`
   - your own MusicXML or MIDI file in Load Score's `path`

Headless: `uv run python custom_nodes/com5fy/workflows/run.py`. Tests: `cd mmmmm && uv run pytest -m ""` (73 pass)
and `uv run --with pytest pytest custom_nodes/com5fy/tests -m ""` (40 pass, W1 with Orchidea included).

## Known limitations

- **One tempo on the way back.** A Sequence has no tempo map yet, so Sequence to Score uses a single bpm. In the test
  score, the 120 BPM run re-quantized at 90 BPM gets approximate rhythms that overlap. M2.2 (`TimeMap`) fixes this.
- **Overlaps and gaps in Sequence to Score.** This is existing `from_sequence` behavior that Orchidea scores share:
  - overlapping notes in one part make music21 split the whole part into two voices, which shows as extra measure
    rests above the staff
  - gaps between notes aren't written as rests
- **Microtones** come back as music21 microtones, so a written quarter-tone accidental may be drawn differently after a
  round trip. The pitch is kept.
- **Text expressions** of any kind ("dolce", "rit.") are read as playing styles.
- **Ties** are matched by pitch. Fingerings and other articulations that carry a value lose the value.
- OSMD titles any score without a title "Untitled Score", as it already did for Orchidea output.

## Feedback wanted

- Should a score without tempo marks default to **60 BPM** (m5's default so far) or **120** (music21, MIDI and most
  notation software)?
- Is a Sequence with **dynamics and styles as state** on every event right? The other option is to put them only on
  the event where the marking appears.
- Should microtones be spelled as **nearest name + cents** (Orchidea's way) or keep quarter-tone names like `C~4`? The
  Sequence Viewer can't read those yet.
- Node names and defaults: "Score to Sequence" with `bpm` 0 meaning "from score"; "Sequence to Score" with default
  thirty-second grid and 60 BPM.
- Should Sequence to Score fill gaps with rests, and keep overlaps in one voice as chords where it can? That would be
  a small follow-up.
