# M2.5: BPF type (break-point function / automation), 2026-11-10

## Status: in progress, resume here

**Background.** The first version showed BPFs only as text, through Preview as Text. The user's feedback, the same
day: BPFs are mainly made by drawing them in a BPF node with a proper curve editor, and nobody needs a text version.
This round built that editor. The user stopped the session before reviewing it, so M2.5 is `[~]`.

**What works.** Everything here was checked in the browser on port 8192, except the light theme.
- **The `m5_BPF` node** ("BPF", `m5/create`) has a canvas curve editor in the node:
  - click empty space to add a point and keep dragging it; drag a point to move it, and it can't pass its neighbours;
  - Shift snaps to a quarter of the labelled grid step; Alt moves only the value;
  - double-click or right-click a point, or select it and press Delete/Backspace, to remove it. Delete does not delete
    the node, and no context menu appears;
  - hovering a point highlights it and shows a label with its time and value; elsewhere the status row shows the
    curve's value under the cursor;
  - the axes are labelled in ms and value, the curve is drawn with the chosen interpolation, and the editor resizes
    with the node. Colours come from ComfyUI's CSS variables and redraw when the palette changes.
- **Widgets:** `duration_ms`, `min`, `max`, `interpolation`, `name` and `unit`. The editor replaces the `points`
  STRING widget under the same name, so points are saved in `widgets_values` and sent to the backend. They survived a
  page reload.
- **Optional `input` (M5_BPF):** with a curve on the input, the node shows it read-only in green and passes it
  through, and the settings widgets are greyed out. "Edit a copy" copies the curve into the editor and disconnects the
  input. Rescale, Resample and Load BPF output can be viewed this way, so Preview as Text is gone from the workflow.
- The backend `_bpf_from_editor` clips points to the box. The `min`/`max` box becomes the BPF's `range`.
- Tests pass, and the headless workflow `M2.5_bpf` passes (see How to test).

**Open design choices**
- Category `m5/create`: drawing is the main way to make a BPF. The node also views, but `m5/data` would hide that it
  creates.
- `exp` is geometric, with no curvature handle (Max `curve~`/DAW-style bends). Should segments get per-point
  curvature?
- Outside its points a BPF holds its end values. The editor's `duration_ms` is only the length of the time axis; the
  BPF has no end time of its own.
- Should a viewed input curve keep its own box (as now) or use the node's widgets?

## What changed

**m5 ([mmmmm/src/m5/bpf.py](https://github.com/dzluke/mmmmm/blob/main/src/m5/bpf.py))**, exported as `m5.BPF` and
`m5.INTERPOLATIONS`:
- **`BPF(points, interpolation="linear", range=None, name="", unit="")`**, a plain dataclass:
  - `points`: `(time_ms, value)` pairs, kept sorted by time. Two points at the same time are a jump; the later one
    wins.
  - `interpolation`: `step`, `linear`, or `exp`. `exp` is geometric: 100 → 400 Hz passes 200 Hz halfway. Through 0
    or a sign change it falls back to linear.
  - `range`: the declared range of the controlled parameter; `None` means the span of the points. `value_range`
    returns whichever applies.
  - `name` and `unit`.
- `evaluate(times)` / `bpf(times)`: before the first point and after the last, the end values are held.
- `resample(step_ms, start_ms=None, end_ms=None)`: the end point is always kept.
- `rescale(low, high, from_range=None)`: maps from `range`, and clears `unit`.
- `from_file` / `to_file`:
  - JSON: `{"points", "interpolation", "range", "name", "unit"}`, or a bare list of pairs;
  - CSV: `time_ms,<name>` rows, with the separator `,`, `;` or tab.
- Also `from_arrays` (for `Descriptor.to_bpf`) and a readable `__str__`.
- Tests: `tests/test_bpf.py`; fixtures `tests/data/swell.bpf.json` and `swell.bpf.csv`.
